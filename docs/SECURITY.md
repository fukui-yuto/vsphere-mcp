# セキュリティポリシー

## 脆弱性の報告方法

vsphere-mcp にセキュリティ上の脆弱性を発見された場合は、責任ある開示にご協力ください。

**セキュリティ脆弱性に関する公開 Issue は作成しないでください。**

代わりに、GitHub の[プライベートセキュリティアドバイザリ](https://github.com/fukui-yuto/vsphere-mcp/security/advisories/new)から報告をお願いします。

### 報告に含めていただきたい情報

- 脆弱性の説明
- 再現手順
- 想定される影響範囲
- 修正案（もしあれば）

### 対応スケジュール

- **確認連絡**: 48時間以内
- **影響評価**: 1週間以内
- **修正リリース**: 深刻度に応じてできる限り早急に対応

## セキュリティに関する設計方針

### 認証情報の管理

- vSphere の認証情報は環境変数（`VSPHERE_PASSWORD`）で管理
- `VSPHERE_PASSWORD_FILE` を使用することで、ファイルベースのシークレット管理にも対応（Docker Secret、Kubernetes Secret など）
- 認証情報はログやエラーメッセージに一切出力されない（ログマスク機能）

### SSL/TLS 設定

- SSL 証明書の検証は**デフォルトで有効**
- `VSPHERE_IGNORE_SSL=true` で検証を無効化可能（開発環境・自己署名証明書向け）
- **本番環境では SSL 検証を絶対に無効化しないこと**

### 破壊的操作の安全装置

- すべての破壊的操作には明示的な `confirm=True` が必要
- 操作は危険度（danger_level）で分類:
  - `low`（低）: 電源オン等
  - `medium`（中）: 電源オフ、シャットダウン、リブート、スナップショット作成等
  - `high`（高）: スナップショット復元・削除、vMotion、クローン、メンテナンスモード等
  - `critical`（最高）: VM 削除等
- すべての操作は構造化ログ（JSON 形式）で記録

### ゲスト OS 操作のリスク

- `execute_guest_command` はゲスト OS 上で任意のコマンドを実行できるため、特に注意が必要
- VMware Tools の認証情報（ゲスト OS のユーザー名/パスワード）が必要
- 実行可能なコマンドの制限は vSphere 側の権限設定に依存
- RBAC ポリシーで `execute_guest_command` へのアクセスを制限することを強く推奨

### RBAC による追加防御

- `VSPHERE_RBAC_POLICY` 環境変数でポリシー JSON ファイルを指定することで、ツール単位のアクセス制御が可能
- 高リスクツール（`delete_vm`、`execute_guest_command`、`batch_power_operation` 等）へのアクセスを運用ポリシーに応じて制限可能
- ポリシー未設定時は全ツールがアクセス可能（後方互換性を維持）

### ネットワークセキュリティ

- MCP サーバーはデフォルトで stdio トランスポートを使用（ローカル実行）
- SSE トランスポートを明示的に設定しない限り、外部ポートは公開されない
- vSphere API との通信は HTTPS を使用

### SSE トランスポート使用時の注意

- SSE トランスポート（`--transport sse`）を使用する場合、指定ポートがネットワーク上に公開される
- 信頼されたネットワーク内でのみ使用するか、リバースプロキシ経由での認証を設定すること
- ファイアウォールルールで接続元 IP を制限することを推奨
- メトリクスポート（`--metrics-port`）も同様にアクセス制限を設定すること

## 本番運用のベストプラクティス

1. vSphere 専用のサービスアカウントを作成し、必要最小限の権限を付与する
2. SSL 証明書の検証を必ず有効にする
3. MCP サーバーは制限された環境で実行する
4. 構造化ログを定期的にレビューし、想定外の操作がないか確認する
5. MCP サーバーと vCenter 間のネットワークセグメンテーションを検討する
6. `VSPHERE_PASSWORD_FILE` を活用し、環境変数に直接パスワードを設定することを避ける
